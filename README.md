# Regime-aware early warning for stablecoin depegs

We test whether a crypto-market stress flag improves next-day depeg forecasts
for DAI, USDC and USDT, using on-chain activity as predictors. Two model
families are compared: logistic regression (logit) and a random forest (RF).
Each is fitted as M1 (on-chain only) and M2 (on-chain + stress flag), trained
on 2022 and tested once on February–April 2023.

The written report (Sections 3–5) is generated by
`model_comparison/build_word_report.py` from the saved outputs in this repo.
Reports are not stored in the repo: the builders write them to
`~/Downloads/stablecoin_regime_report/` (the .docx, an optional PDF, and the
figure PNGs).

All commands below are run from the repository root.

## 1. How the repo is organised

```
dataset/                 Raw input data (read-only)
depeg_labeller/          Step 1: builds the depeg outcome label
regime_classifier/       Step 2: builds the daily stress / normal regime flag
replication/             Replicates Tables 3–4 of Lee, Chiu & Hsieh (2025); standalone
logit/                   Step 3: logit models (M1, M2) and the M3 interaction test
random_forest/           Step 4: random-forest models (M1, M2)
model_comparison/        Step 5: logit vs RF tests, alert metrics, and the report builders
  placebo.py               shared helpers for the placebo (fake-flag) test
  outputs/                 compare_models.py + threshold_event_metrics.py results
  outputs_score/           score_variant.py results
mid_term_presentation/   Earlier work, kept for reference; not needed for the report
requirements.txt
```

Each step folder holds its scripts plus an `outputs/` (or `results/`) folder
with the exact outputs the report was built from. Notebooks
(`depeg_labeller/audit.ipynb`, `regime_classifier/regime_audit.ipynb`) are
audits for checking the label and regime; the report does not read them.

## 2. Where the data sit

### Raw data: `dataset/`

Never edited by any script. Each file is stored as CSV (read by the code) and
XLSX (for viewing). `dataset/README.csv` documents every column.

| File | Content | Coverage | Source |
|---|---|---|---|
| `prices.csv` | Daily OHLC and volume for BTC, ETH, BUSD, DAI, USDC, USDT | 2022-01-01 to 2023-12-31 | Yahoo Finance, CryptoCompare as fallback |
| `sentiment.csv` | Crypto Fear & Greed index | 2022-01-01 to 2023-12-31 | alternative.me |
| `onchain_2022_base.csv` | Daily Ethereum on-chain activity per coin | 2022-04-01 to 2022-11-01 | Stanford ERC-20 stablecoin transfers |
| `onchain_2023_base.csv` | The same measures for 2023 | Feb–Apr 2023 | Google BigQuery Ethereum export |
| `supply.csv` | Circulating supply | 2022–2023 | DefiLlama (not used by the models) |
| `news_events.csv` | Dated stablecoin news events | Apr–Oct 2022 | Not used by the models |

The 2022 and 2023 on-chain files come from different providers (see the
report's limitations).

### Processed data

| File | Made by | What it is |
|---|---|---|
| `depeg_labeller/results/depeg_labels_dynamic.csv` | `dynamic_depeg.py` | Outcome: does the coin breach its volume-scaled depeg band on day t+1 |
| `regime_classifier/outputs/market_regime.csv` | `regime_classifier.py` | Daily `stress` flag (2 of 3: bearish BTC, bearish ETH, Fear & Greed < 40) |
| `logit/outputs/logit_decomposition/model_panel.csv` | `logit_oos.py` | Merged modelling panel (coin × day): features, label, flag |
| `model_comparison/outputs/*_predictions.csv` | `compare_models.py` | Out-of-sample forecasts for both models, both periods |

The logit and RF scripts build the modelling panel from these files with the
same loader (`logit/logit_oos.py: load_inputs`), so both models see identical
observations.

## 3. How to reproduce

### Setup

```sh
pip install -r requirements.txt
```

### Run order

Steps must run in this order, because each reads the previous step's outputs.

```sh
# 1. Outcome label and regime flag (overwrite in place)
python depeg_labeller/dynamic_depeg.py
python regime_classifier/regime_classifier.py

# 2. Logit
python logit/logit_oos.py                --out logit/outputs/logit_decomposition
python logit/regime_lag_sensitivity.py   --out logit/outputs/regime_lag_sensitivity
python logit/interaction_test.py         --out logit/outputs/interaction_weekly_initial

# 3. Random forest
python random_forest/rf_oos.py                    --out random_forest/outputs/rf_decomposition
python random_forest/rf_regime_lag_sensitivity.py --out random_forest/outputs/regime_lag_sensitivity

# 4. Head-to-head tests (compare_models.py must run before the other two)
python model_comparison/compare_models.py          # bootstrap + 89 placebo flags; slowest step
python model_comparison/threshold_event_metrics.py
python model_comparison/score_variant.py

# 5. Reports
python model_comparison/build_word_report.py       # the report (.docx) + figures, to ~/Downloads
python model_comparison/build_report.py            # optional longer technical PDF, to ~/Downloads

# Standalone: replication of the reference paper
python replication/replication.py
```

**Output folders must be empty.** The scripts in steps 2–3 refuse to write into
a folder that already has files, so a run can't overwrite saved results by accident.
To check our numbers, rename the saved folder first (for example
`logit/outputs/logit_decomposition` → `logit_decomposition_saved`), rerun, and
compare. Without `--out`, the scripts write to a new timestamped folder,
which the report builders do not read.

All models use fixed settings and `random_state=0`, so reruns should match the
saved outputs. Run manifests (`run_manifest.json`, `manifest.json`) record
input file hashes. The paths inside them are from the original author's machine.

**Logit interaction test (Section 4.4).** The report reads
`logit/outputs/interaction_weekly_initial/`, made by the current
`logit/interaction_test.py` (within-coin scaling, coin fixed effects,
week-clustered errors; details in `logit/README_interaction_test.md`). A rerun
reproduces it exactly. `logit/outputs/interaction_test/` is an older
date-clustered version, kept for reference only; nothing reads it.

## 5. Other files

- `depeg_labeller/label_validation.py`: compares our dynamic band with the
  original 30-day and static 25 bp bands (plots in `depeg_labeller/results/`).
  A diagnostic, not the label used by the models.
- `regime_classifier/regime_audit_helpers.py`: helpers for the regime notebook.
- `mid_term_presentation/`: mid-term scripts, EDA and data snapshots, plus
  early utilities (`build_onchain_data.py`, `threshold_audit.py`,
  `read_prices_csv.py`). Not needed to reproduce the report; see its own README.
